# xui-deployer

Интерактивный установщик панели [3X-UI](https://github.com/MHSanaei/3x-ui) с архитектурой
**«всё TCP на 443»**: nginx принимает единственный публичный порт и по SNI разводит трафик
между REALITY и собственным TLS-фронтом (WebSocket, XHTTP, панель, подписка).
Воспроизводит эталонную связку 3X-UI + nginx, проверенную в бою.

```
                        ┌─────────────────────────────────────────────────────────┐
                        │                     VPS (Ubuntu 24.04)                  │
                        │                                                         │
 интернет ── 443/tcp ──►│ nginx stream (ssl_preread + PROXY protocol)             │
                        │   │                                                     │
                        │   ├─ SNI = домен ────────► Xray REALITY   :10443        │
                        │   │                        (клиенты)                    │
                        │   │                        посторонние ──► self-steal   │
                        │   │                                         :10447      │
                        │   └─ default ────────────► nginx TLS-фронт :10446       │
                        │        (IP-сертификат)      │                             │
                        │                             ├─ /ws-путь ──► Xray :10451  │
                        │                             ├─ /sub-путь ─► client-sub ─► панель :2097
                        │                             ├─ /panel-путь ► панель :22130 (TLS)
                        │                             └─ / ─────────► лендинг-заглушка
                        │        (SNI = поддомен)     vhost XHTTP (свой серт)      │
                        │                             └─ /xhttp-путь ► Xray :10444 │
                        └─────────────────────────────────────────────────────────┘
```

- **один UUID / один клиент** во всех inbound – подписка отдаёт все ссылки одной пачкой;
- **панель и подписка слушают только 127.0.0.1** – снаружи их не видно, доступ через случайные пути на 443;
- **сертификаты Let's Encrypt** (acme.sh): на IP (профиль `shortlived`, ~6 дней, автопродление),
  на домен и на поддомен XHTTP;
- **UFW**: наружу открыты только SSH, 80 (для acme.sh) и 443;
- установщик панели **закреплён по версии и SHA256**, сервис подписки client-sub поставляется в репозитории.

## Требования

- чистый VPS: Ubuntu 22.04/24.04 или Debian 12, x86_64/aarch64, systemd, root;
- свободный порт 443;
- для полноценной маскировки – свой домен с A-записью на сервер
  (и поддомен для XHTTP, например `xhttp.example.com`, туда же).
  Без домена скрипт работает: REALITY маскируется под чужой сайт, XHTTP идёт по IP.

## Установка

После публикации репозитория (замените `x0cdn` на аккаунт):

```bash
curl -fsSL https://raw.githubusercontent.com/x0cdn/3xui-deployer/main/get.sh | bash
```

Или вручную:

```bash
git clone https://github.com/x0cdn/3xui-deployer.git
cd 3xui-deployer
sudo bash install.sh
```

Полезные флаги:

```bash
bash install.sh --dry-run                     # прогон мастера без изменений системы
sudo bash install.sh -y --domain vpn.example.com --protocols reality,ws,xhttp
sudo bash install.sh -y --domain vpn.example.com --cf-token <токен> --ssh-port 37951
```

| Флаг | Назначение |
|---|---|
| `--domain ДОМЕН` | свой домен: REALITY self-steal + поддомен XHTTP |
| `--sni САЙТ` | чужой сайт для маскировки (если без домена) |
| `--xhttp-sub ПОДДОМЕН` | поддомен XHTTP (по умолчанию `xhttp.<домен>`) |
| `--protocols СПИСОК` | `reality,ws,xhttp`, `all` или `minimal` |
| `--user ИМЯ` | имя первого клиента (по умолчанию `admin`) |
| `--ssh-port ПОРТ` | сменить порт SSH до включения UFW |
| `--cf-token ТОКЕН` | Cloudflare API token: DNS-01, сертификаты без порта 80 |
| `--email EMAIL` | email для acme.sh |
| `--no-ufw` | не трогать файрвол |
| `--no-client-sub` | подписка отдаётся панелью напрямую, без посредника |
| `--dry-run` | мастер и план без изменений системы |
| `-y` / `--yes` | без вопросов, значения по умолчанию/из флагов |

## Какие вопросы задаёт мастер

1. **Свой домен для маскировки** (A-запись на сервер). Enter – без домена.
2. **Cloudflare API token** (если домен задан): DNS-01 позволяет выпустить сертификат,
   не открывая порт 80. Enter – выпуск через порт 80 (HTTP-01).
3. **Протоколы подключений** – мультивыбор, по умолчанию отмечены все три:
   REALITY, VLESS-WS, XHTTP.
4. **Поддомен для XHTTP** (если выбран XHTTP и есть домен), по умолчанию `xhttp.<домен>`.
   Нужна A-запись поддомена на этот сервер.
5. **Имя первого клиента** (по умолчанию `admin`).
6. **Логин/пароль панели**: сгенерировать автоматически (случайные, порт и путь тоже случайные)
   или ввести свои.
7. **Ставить ли client-sub** – посредник подписки с учётом приложения (по умолчанию да).
8. **Новый порт SSH** (Enter – оставить текущий).
9. **Настроить ли UFW** (по умолчанию да).
10. **Подтверждение плана** – сводка всех параметров перед стартом.

Если задан `--sni` или сайт маскировки не указан, скрипт сам подбирает живой сайт
с TLS 1.3 + HTTP/2 (`dl.google.com`, `www.amazon.com`, …).

## Какие подключения создаются

Один клиент (UUID + subId общие) добавляется во все выбранные inbound.
Отпечаток браузера (fingerprint) во всех подключениях – **firefox**.

### 1. REALITY – основной вход

| Параметр | Значение |
|---|---|
| Протокол | VLESS + XTLS Vision (`flow=xtls-rprx-vision`) |
| Адрес в ссылке | `домен:443` (без домена – `IP:443`) |
| Listen | `127.0.0.1:10443` (наружу выводит nginx stream) |
| Security | REALITY, `fingerprint=firefox`, `spiderX=/` |
| SNI / serverNames | ваш домен (или сайт маскировки) |
| shortId | случайные 16 hex-символов |
| Ключи | свежая пара X25519 от API панели |
| Self-steal | посторонние попадают на заглушку `127.0.0.1:10447` с сертификатом домена |
| PROXY protocol | `acceptProxyProtocol=true` (nginx stream передаёт реальный IP) |
| Sniffing | http/tls/quic |

### 2. VLESS-WS – WebSocket через nginx

| Параметр | Значение |
|---|---|
| Адрес в ссылке | `IP:443`, `security=tls`, `alpn=http/1.1`, `fp=firefox` |
| Listen | `127.0.0.1:10451`, `security=none` (TLS терминирует nginx) |
| Путь | случайный, например `/a1b2c3d4e5` (точное совпадение в nginx) |
| TLS-сертификат | Let's Encrypt на IP |

### 3. XHTTP TLS – отдельный поддомен

| Параметр | Значение |
|---|---|
| Адрес в ссылке | `поддомен:443`, `security=tls`, `sni=поддомен`, `fp=firefox`, `alpn=h2,http/1.1` |
| Listen | `127.0.0.1:10444`, `security=none` |
| Режим | `packet-up`, паддинг `xPaddingBytes=100-1000`, `scMaxBufferedPosts=30` |
| Путь | случайный; nginx проксирует и путь, и `<путь>/<session>` |
| TLS-сертификат | Let's Encrypt на поддомен, отдельный vhost |
| Без домена | путь в общем фронте по `IP:443`, режим `auto` |

### Панель и подписка (не inbound, но тоже создаются)

- **Панель**: случайный порт (20000+), случайный путь `/SluchaynyyPut/`, логин/пароль из мастера.
  Слушает `127.0.0.1`, доступ снаружи: `https://IP/путь/` через nginx.
- **Подписка**: `https://IP/sub-путь/<subId>` – одна ссылка на все протоколы.
  Пути подписки (обычная, JSON, Clash) случайные; `subEncrypt=true`, заголовок профиля – `xui-deployer`.
- **client-sub** (опционально): systemd-сервис на `127.0.0.1:10460` перед подпиской панели.
  Правит ответ панели под конкретное приложение (подробности – ниже).

### client-sub: одна подписка для разных приложений

Панель отдаёт всем клиентам один и тот же ответ. client-sub стоит между nginx и подпиской
панели и подстраивает его:

| Клиент | Что получает |
|---|---|
| Mihomo / Clash Verge / FlClash / Mihomo Party | Clash-YAML панели + AmneziaWG из подписки `<subId>-awg`, группа авто-выбора «Авто», безопасный DNS (fake-ip + DoH) |
| Karing, Hiddify, sing-box и др. (просят Clash) | тот же YAML, но без AmneziaWG и без правил маршрутизации – их понимает только Mihomo |
| Hiddify | панели представляется без слова Clash в User-Agent: иначе она отдаёт YAML, который Hiddify ломает |
| Xray / JSON-подписка | VLESS-пользователям без `encryption` проставляется `"none"` |
| Все клиенты | из `Subscription-Userinfo` убирается `expire=0` (иначе показывается 01.01.1970); из списка ссылок удаляются `vpn://` и `tg://` |

Необязательные файлы (правки применяются без перезапуска сервиса):

- `/etc/client-sub/rules.yaml` – раздельная маршрутизация: через VPN идёт только перечисленное,
  остальное напрямую. Например:

  ```yaml
  via_vpn:
    - GEOSITE,youtube
    - DOMAIN-SUFFIX,example.org
    - IP-CIDR,203.0.113.0/24
  direct_dns:
    - https://9.9.9.9/dns-query   # DoH для всего, что идёт напрямую
  ```

  Проверка файла (в том числе названий категорий GEOSITE/GEOIP):
  `python3 /usr/local/lib/client-sub/client_sub.py --check-rules`.
  При установке правила автоматически передаются панели: Happ получает заголовок
  `Routing`, JSON-подписка Xray – встроенный профиль маршрутизации. Если файл создан
  или изменён позже, примените его командой `xui-deployer routing` (она же отключает
  маршрутизацию, если файл удалён). Файл должен быть читаем сервису:
  `chmod 644 /etc/client-sub/rules.yaml`.

- `/etc/client-sub/sni-grace.json` – карта «прежнее имя сайта REALITY → нынешнее» на время
  льготного срока после смены маскировки: `{"old.example.com": "new.example.com"}`.
  В подписку попадает только нынешнее имя.


## Порты и файрвол

| Порт | Кто слушает | Наружу |
|---|---|---|
| 443/tcp | nginx stream | да |
| 80/tcp | acme.sh на время выпуска/продления | да (в UFW) |
| SSH (текущий или новый) | sshd | да |
| 10443/10444/10446/10447/10451 | Xray / nginx | нет (127.0.0.1) |
| порт панели, 2097, 10460 | панель / подписка / client-sub | нет (127.0.0.1) |

UFW: `default deny incoming`, разрешены только SSH, 80 и 443.

## Сертификаты

acme.sh + Let's Encrypt, ключи ec-256, автопродление по cron:

| Сертификат | Путь | Особенности |
|---|---|---|
| IP | `/root/cert/ip/` | профиль `shortlived` (~6 дней), продление каждые ~4 дня |
| Домен | `/root/cert/<домен>/` | HTTP-01 (порт 80) или DNS-01 Cloudflare |
| Поддомен XHTTP | `/root/cert/<поддомен>/` | то же |

После продления – `systemctl reload nginx`. Если LE не выдал сертификат на IP
(лимиты), выдаётся самоподписанный запасной – клиенты WS будут ругаться на TLS,
пока не появится настоящий.

## Результат и управление

- `/root/xui-deployer.txt` – панель, логин/пароль, подписка, ссылки по протоколам (chmod 600);
- `/etc/xui-deployer/state.env` – машинное состояние установки;
- команда `xui-deployer`:

```bash
xui-deployer info      # реквизиты и ссылки
xui-deployer status    # сервисы, порты, UFW, сертификаты
xui-deployer links     # содержимое подписки (ссылки по протоколам)
xui-deployer restart   # x-ui + nginx + client-sub
xui-deployer routing   # применить /etc/client-sub/rules.yaml к Happ и JSON-подписке
xui-deployer backup    # архив БД, конфигов и сертификатов в /root
```

Конфиги nginx: `/etc/nginx/xui-stream.conf`, `/etc/nginx/conf.d/xui-front.conf`
(перезаписываются установщиком; дополнительные сайты добавляйте отдельными файлами в `conf.d`).
Логи установки: `/var/log/xui-deployer-panel-install.log`, `/var/log/xui-deployer-acme.log`.

## Безопасность

- Установка только на **чистый** сервер: скрипт проверяет, что 3X-UI ещё не стоит и 443 свободен.
- Установщик 3X-UI (`v3.11.0`) скачивается с GitHub и проверяется по закреплённому SHA256 –
  подменённый файл не выполнится.
- Порт SSH меняется **до** включения UFW; текущий порт всегда разрешается до `enable`.
- Файлы с реквизитами доступны только root.
- Скрипт не трогает существующие сайты nginx (кроме дефолтного `sites-enabled/default`,
  который мешает acme.sh занимать порт 80).
